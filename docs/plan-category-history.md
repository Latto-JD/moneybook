## 1. 목표

기록 탭의 카테고리별 합계 줄에서 카테고리 하나를 누르면, 그 카테고리의 전체 기간 거래를 합계·건수와 함께 보여 주는 "사용 이력" 화면을 연다. 목록은 최신순·오래된순(월별 묶음)과 금액 큰 순·작은 순(평평한 목록)으로 정렬할 수 있다.

## 2. 사용자 스토리

- 사용자로서 이번 달 식비가 많아 보일 때, 식비를 눌러 지금까지 식비를 언제 어디에 썼는지 한 목록으로 보고 싶다.
- 사용자로서 그 카테고리에 지금까지 모두 얼마를 몇 건 썼는지, 달마다 얼마였는지 알고 싶다.
- 사용자로서 그 카테고리에서 가장 크게 쓴 거래나 가장 오래된 거래를 정렬해서 찾고 싶다.
- 사용자로서 이력에서 잘못 적은 거래를 발견하면 그 행을 눌러 바로 고치고 싶다.
- 사용자로서 기록이 많아도 화면이 느려지지 않고 필요한 만큼 더 불러 보고 싶다.
- 사용자로서 수입 카테고리(예: 부수입)도 같은 방식으로 보고 싶다.

## 3. 범위 / 범위 밖

**범위**
1. 진입: 기록 탭 월 카드의 "카테고리별 지출 / 카테고리별 수입" 막대 행을 누르면 이력 화면으로 간다(4.3 비교, 안 A).
2. 이력 화면(새 패널 `#panel-history`): 머리(뒤로, 카테고리 이름, 지출/수입, 사용 안 함 표시), 요약 카드(전체 합계·건수·기간), **정렬 선택(4종)**, 목록(날짜순은 월별 묶음 + 월 소계, 금액순은 평평한 목록), 30건씩 "더 보기", 빈 상태, 오류·다시 시도.
3. 행 누르기: 기존 기록 탭 수정 흐름(`startEdit`)을 그대로 쓴다.
4. 백엔드: 읽기 전용 새 API `GET /api/category-history` 1개(`sort` 포함). **DB 스키마·인덱스 변경 없음, 운영 마이그레이션 없음**(5.4에서 정렬 포함해 다시 판단).
5. 출렁임 유닛 추가(7장), 움직임 줄이기 규칙 유지, 360/768, 라이트·다크, 접근성.

## 4. 현재 상태 조사

### 4.1 거래 목록은 어떻게 나오나
- **[사실]** 기록 탭 월 카드는 `.month-nav`(이전/다음 달) 아래 `#month-summary`(카테고리별 수입 → 카테고리별 지출 막대) 와 `#tx-list` 를 한 카드에 그린다(`index.html:93-102`).
- **[사실]** 목록은 **월 단위**다. `loadMonth` 가 `listTransactions(month)`, `summary(month)`, `statsCategories(month, month, 'income')` 를 함께 부른다(`record.js:581-597`).
- **[사실]** **필터는 없고 수입·지출이 섞여 나온다.** 날짜별 `li.tx-group > h3.tx-date + ul.tx-rows > li.tx-row`, 날짜 머리에 그날 수입·지출 합계(`record.js:489-522`).
- **[사실]** 행은 버튼 하나(`.tx-edit`, 누르면 `startEdit`)와 삭제 버튼(`.tx-del`)으로 되어 있다(`record.js:524-552`). `startEdit` 은 폼을 채우고 `#tx-form` 으로 `scrollIntoView` 후 금액에 포커스한다(`record.js:358-381`). 사용 안 함 카테고리 거래도 고칠 수 있다(api.md 4.3 카테고리 유지 예외).
- **[사실]** `#month-summary` 의 막대 행은 그 달의 카테고리를 **묶지 않고 전부** 보인다(`record.js:443-465`, 지출은 `summary.byCategory`, 수입은 `stats/categories`). 사용 안 함 카테고리의 과거 거래도 포함된다(api.md 5.1). 지금은 누를 수 없는 `li` 다.
- **[사실]** 앱의 선택 UI 는 모두 `.segmented`(버튼 + `aria-pressed`)이고 `<select>` 는 쓰지 않는다(`index.html:41,121,136,159`). `.segmented` 는 열 너비가 같은 격자이고 항목 높이는 `--touch-min`(44px)이다(`components.css:132-133`).

### 4.2 기존 API 가 category 필터를 지원하나
- **[사실]** `GET /api/transactions` 는 `month` **필수**이고 `type`·`category`·정렬 파라미터가 없다(api.md 4.1, `transactions/routes.js:53-62`).
- **[사실]** 카테고리별 월 합계는 `GET /api/stats/category-monthly`(최대 24개월, api.md 5.4)로 얻을 수 있지만 거래 목록은 없다.
- **[사실]** 카테고리 관리의 `usedCount` 는 "같은 유형·같은 이름의 전 기간 거래 건수"다(api.md 3A.1, `category-manager.js:55,73`).
- **판단:** frontend 만으로는 달마다 `GET /api/transactions` 를 거꾸로 호출해 걸러야 하고, 금액순 정렬은 전체를 다 받기 전에는 불가능하다. **backend 에 읽기 전용 API 1개를 추가한다**(5장).
- **[사실]** 인덱스는 `transactions_user_date_idx (user_id, date)` 하나다(`schema.sql:43`).

## 5. API (backend, B-H1~B-H2)

`docs/api.md` 를 **v4.4** 로 올리고 새 절(예: 4.5)에 아래 계약을 쓴다. backend 가 구현 전에 먼저 반영한다. 추가 전용이며 기존 API·응답·에러 코드는 바뀌지 않는다.

### 5.1 GET /api/category-history?type=&category=&sort=&limit=&cursor=

세션 필수(1.5). 경로는 거래 `:id` 경로(`/api/transactions/:id`)와 겹치지 않게 따로 둔다(`router.js:27-46` 는 먼저 맞는 정규식을 쓰므로 `/api/transactions/history` 는 PUT/DELETE 에서 `:id` 로 잡힌다). 다른 메서드는 405 `Allow: GET`.

| 파라미터 | 규칙 | 오류 |
|---|---|---|
| `type` | 필수, `expense` \| `income` | 400 `fields.type` |
| `category` | 필수, 문자열 1~50 코드포인트, 제어문자 없음. **정규화·대소문자 무시 없이** 거래의 `category` 문자열과 정확히 같은 것만 | 400 `fields.category` |
| `sort` | 선택, `date_desc`(기본) \| `date_asc` \| `amount_desc` \| `amount_asc`. 빈 값(`sort=`)도 400 | 400 `fields.sort` |
| `limit` | 선택, 10진 정수 1~100, 기본 30 | 400 `fields.limit` |
| `cursor` | 선택, **같은 `sort`** 로 받은 직전 응답의 `nextCursor` 그대로(불투명 문자열) | 형식 오류·정렬 불일치 400 `fields.cursor`(5.2) |

- 알 수 없는 파라미터는 무시한다. `today` 는 받지 않는다.
- 카테고리 목록(`categories`)에 그 이름이 있는지 확인하지 않는다(사용 안 함·목록 밖 문자열도 이력은 보여야 한다). 그래서 카테고리를 읽지 않고, 지연 생성(3A.1) 같은 쓰기도 일으키지 않는다.
- 없는 이름이면 404 가 아니라 200 빈 결과다.

**정렬 순서 (동점 처리 포함, 항상 전순서)**

| `sort` | ORDER BY | 뜻 |
|---|---|---|
| `date_desc` | `date desc, created_at desc, id desc` | 최신순(`GET /api/transactions` 와 같음) |
| `date_asc` | `date asc, created_at asc, id asc` | 오래된순(정확히 최신순의 역순) |
| `amount_desc` | `amount desc, date desc, created_at desc, id desc` | 금액 큰 순. 같은 금액은 최신 먼저 |
| `amount_asc` | `amount asc, date desc, created_at desc, id desc` | 금액 작은 순. **같은 금액은 역시 최신 먼저** |

- 같은 금액의 동점은 두 금액순 모두 "최신 먼저"로 한다 [권장]. 금액 작은 순에서 같은 금액(예: 커피 4,500원 여러 건)을 오래된 것부터 보이는 것은 어색하기 때문이다. 그래서 `amount_asc` 는 키 방향이 섞인다(5.2 조건식).
- `id` 가 마지막 키라 어떤 데이터에서도 순서가 하나로 정해진다(같은 요청을 두 번 보내면 같은 순서).

**200**
```json
{
  "type": "expense",
  "category": "식비",
  "sort": "date_desc",
  "total": 1190000,
  "count": 58,
  "firstDate": "2026-03-02",
  "lastDate": "2026-10-28",
  "months": [
    { "month": "2026-10", "total": 400000, "count": 21 },
    { "month": "2026-09", "total": 410000, "count": 20 },
    { "month": "2026-03", "total": 380000, "count": 17 }
  ],
  "transactions": [
    { "id": "uuid", "type": "expense", "amount": 12000, "category": "식비", "memo": "점심", "date": "2026-10-28", "createdAt": "2026-10-28T03:12:45.123Z" }
  ],
  "nextCursor": "eyJzIjoi..."
}
```

| 필드 | 설명 |
|---|---|
| `sort` | 적용된 정렬(기본값이면 `date_desc`) |
| `total`, `count` | 세션 사용자의 같은 `type`·같은 `category` 거래 **전 기간** 합계·건수(미래 날짜 포함). **정렬과 무관.** `count` 는 같은 시점 `GET /api/categories` 의 그 카테고리 `usedCount` 와 같다 |
| `firstDate`, `lastDate` | 가장 이른·늦은 거래 날짜. 거래가 없으면 `null`. 정렬과 무관 |
| `months` | 거래가 **있는** 달만, **항상 최신 달 먼저**(정렬과 무관, 빈 달은 채우지 않음). frontend 는 날짜순 화면의 월 소계에만 쓰고 순서는 화면 쪽에서 맞춘다 |
| `transactions` | 거래 객체(4장과 같은 모양) 최대 `limit` 개, 위 정렬 순서 |
| `nextCursor` | 다음 쪽이 있으면 문자열, 없으면 `null` |

- 요약(`total`·`count`·`firstDate`·`lastDate`·`months`)은 `cursor`·`sort` 와 관계없이 매번 같은 방식으로 계산해 돌려준다(frontend 는 첫 쪽 값을 쓰고, 다음 쪽에서 값이 달라졌으면 새 값으로 바꾼다).
- 빈 결과: `total: 0, count: 0, firstDate: null, lastDate: null, months: [], transactions: [], nextCursor: null`(`sort` 는 요청 값).
- 합계는 bigint 로 더하고 JS `Number` 로 돌려준다(건당 최대 1억, 정수 안전 범위 안).

### 5.2 커서(키셋) 규칙
- 커서 = base64url(JSON) `{ s, a, d, c, i }`: `s` 정렬 이름, `a` 금액(금액순만), `d` 날짜, `c` `created_at`, `i` id. 그 쪽 **마지막 거래**의 값이다. OFFSET 은 쓰지 않는다(중간에 거래가 추가·삭제되어도 겹치거나 빠지지 않게).
- 다음 쪽 조건(`K = (date, created_at, id)`, 커서 값은 `$a, $k = ($d, $c, $i)`):
  - `date_desc`: `K < $k`
  - `date_asc`: `K > $k`
  - `amount_desc`: `amount < $a or (amount = $a and K < $k)`
  - `amount_asc`: `amount > $a or (amount = $a and K < $k)` (금액은 오름차순, 동점 안은 최신 먼저라 방향이 섞인다. 행 비교 `(amount, date, …) > (…)` 한 줄로 쓰면 틀린다)
- **함정:** 응답의 `createdAt` 은 밀리초 ISO 문자열이지만 DB `created_at` 은 마이크로초다. 커서에 응답의 `createdAt` 을 넣어 비교하면 같은 밀리초 안의 행이 빠지거나 겹친다. `c` 에는 **DB 값을 마이크로초 그대로**(예: 텍스트 또는 epoch 마이크로초 정수) 담는다.
- **정렬이 바뀐 커서는 400 으로 거부한다** [결정]. `cursor.s !== sort`(쿼리에 `sort` 가 없으면 `date_desc` 로 보고 비교)이면 400 `VALIDATION_ERROR`, `fields.cursor` = "정렬이 바뀌어 목록 위치를 쓸 수 없어요. 처음부터 다시 불러와 주세요."
  - 이유: "조용히 처음부터"로 돌려주면 frontend 가 더 보기로 이어 붙일 때 첫 쪽 행이 중복으로 붙는데, 서버 응답만으로는 그것을 알 수 없다. 400 이면 잘못이 바로 드러난다. frontend 는 정렬을 바꿀 때 항상 커서 없이 처음부터 부르므로(6.4) 정상 흐름에서는 이 400 이 나오지 않는다.
- 커서 검증: base64url 해독 실패, JSON 아님, 필드 누락, `s` 가 4종 밖, 금액순인데 `a` 가 1~100,000,000 정수가 아님, 날짜·시각·UUID 형식 오류는 400 `fields.cursor` "목록 위치가 올바르지 않아요."
- 커서는 사용자·카테고리를 담지 않으며, 다른 카테고리 요청에 섞어 보내도 그 카테고리 안의 위치 조건으로만 쓰인다(데이터가 새지 않음).

### 5.3 사용자 격리
- 모든 쿼리는 `user_id = 세션 사용자` 조건을 갖는다. 다른 사용자가 같은 이름의 카테고리를 써도 결과에 섞이지 않는다.
- 커서에 다른 사용자의 거래 값을 넣어도 위치 비교 값으로만 쓰이고 그 행을 읽지 않는다.

### 5.4 인덱스·성능 (정렬 포함 재판단)
- **결론: 인덱스 없이 간다. 스키마·인덱스 변경 없음, 운영 마이그레이션 없음.**
- 근거: 어느 정렬이든 실행 계획은 같다. 기존 `(user_id, date)` 인덱스로 그 사용자 행(기준 5,000건)만 읽고 → `type`·`category` 로 거른 뒤(기준 1,000건) → 정렬해 앞 `limit+1` 개만 고른다(top-N 정렬, 메모리 안). 1,000건 정렬은 밀리초 단위라 금액순이 날짜순보다 눈에 띄게 느려지지 않는다. 쪽마다 같은 일을 다시 하지만 1,000건 / 30 = 34쪽을 끝까지 넘겨도 쪽당 비용은 같다.
- 쿼리는 요청당 2개(목록 1, 요약 1, 요약은 `group by` 달)로 끝낸다. 요청당 쿼리가 거래 수에 비례해 늘지 않는다.
- 기준: 한 사용자 거래 5,000건(그중 한 카테고리 1,000건, 같은 금액 묶음 포함) 로컬 PGlite 에서 **4가지 정렬 각각 첫 쪽·마지막 쪽** 요청이 300ms 이하. B-H2 테스트에서 시간을 기록하고 QA 는 기록만 확인한다.
- 이 기준을 못 넘으면 인덱스(예: `(user_id, type, category, date, created_at, id)` 와 금액순용 `(user_id, type, category, amount, …)`)를 검토한다. 이 경우 **운영 마이그레이션(백업 → `db:migrate:prod` → 배포)이 필요해지므로** 구현 전에 메인 세션에 먼저 알린다.

### 5.5 배포
- 추가 전용 API 라 frontend 와 같은 푸시로 배포해도 된다. 순서 제약 없음.

## 6. 화면 (frontend)

### 6.1 진입 (F-H4)
- `#month-summary` 의 각 막대 행(`li`) 안 내용을 버튼 하나로 감싼다(`class` 는 기존 `cat-bar-head`·`bar-track` 유지, 오른쪽에 `icon--chevron`). 막대는 장식(`aria-hidden`) 그대로.

- 누르면 선택(`type`, `category`)을 모듈 상태에 두고 `location.hash = '#history'`. 돌아올 때 포커스를 되돌릴 대상(같은 type·category 의 막대 버튼)을 기억한다.
- 누를 영역은 높이 44px 이상(plan-redesign 높이 규칙).

### 6.2 패널과 이동 (F-H2)
- `index.html` 에 `section#panel-history` 추가, `tabs.js` 의 `TABS` 에 `history`, `TAB_LINK.history = 'record'`(탭바는 기록 활성). 하단 탭은 늘리지 않는다.
- 머리: 카테고리 관리와 같은 `.cat-top`(뒤로 링크 `href="#record"`, `h1#hist-title tabindex="-1"`). 들어오면 `h1` 에 포커스.
- 선택은 메모리에만 둔다. 새로고침 등으로 선택 없이 `#history` 가 열리면 `location.replace('#record')` 로 기록 탭에 간다(OQ-H8).
- 뒤로(링크 또는 브라우저 뒤로): 기록 탭으로 가고, 기억한 막대 버튼이 있으면 그 버튼에 포커스, 없으면 `#month-title-h`.

### 6.3 이력 화면 구성 (F-H3)
위에서 아래로:
1. **제목:** `h1` = `"{카테고리}"`, 그 아래 캡션 `"지출 사용 이력"` / `"수입 사용 이력"`. 카테고리가 사용 안 함이면(`GET /api/categories` `items` 로 판단) `"사용 안 함"` 배지. 견본(swatch)은 기록 목록과 같은 `vizMap` 번호.
2. **요약 카드 `#hist-summary`:** 전체 합계(지출은 `−`, 수입은 `+` 부호, 기존 `formatSignedWon`), `"{count}건"`, 기간 `"2026년 3월 2일 ~ 2026년 10월 28일"`(같은 날이면 한 날짜). **정렬과 무관하게 같다.** 거래 0건이면 카드·정렬 선택 대신 빈 상태(6.5).
3. **정렬 선택 `#hist-sort`:** 요약 카드 아래, 목록 카드 위. 기존 `.segmented`(전체 너비, 4칸 같은 너비) + `role="group"` `aria-label="정렬"`, 버튼 4개 `aria-pressed`:
   - `최신순`(기본) / `오래된순` / `금액 큰순` / `금액 작은순`
   - `<select>` 는 쓰지 않는다(앱에 없는 패턴, 4.1). 360px 에서 한 칸 약 76px 이라 네 글자 라벨이 한 줄에 들어간다. 들어가지 않으면 `style.css` 에서 이 그룹만 `font-size` 를 한 단계 줄이고, 그래도 안 되면 2×2 격자로 바꾼다(높이 44px 유지).
   - 거래가 1건뿐이어도 보인다(정렬 결과는 같음).
4. **목록 카드 `#hist-list`:** 정렬에 따라 모양이 다르다.
   - **날짜순(최신순·오래된순):** 월 묶음 `li.tx-group > h3.list-head.tx-date` + `ul.tx-rows > li.tx-row`(기존 클래스로 같은 높이·정렬을 받는다). 월 묶음 순서는 정렬 방향을 따른다(오래된순이면 가장 오래된 달이 위, 그 달 안의 행도 오래된 것부터).
     - 월 머리: 왼쪽 `"2026년 10월"`, 오른쪽 `"−400,000원 · 21건"`. 값은 **응답의 `months`** 에서 달 이름으로 찾아 쓴다(쪽 나눔으로 그 달 행이 일부만 불러와져도 소계는 그 달 전체).
     - 행: 왼쪽 날짜 `"10월 28일 (화)"`(연도는 월 머리에 있음), 가운데 메모(없으면 흐린 `"메모 없음"`), 오른쪽 금액.
   - **금액순(큰순·작은순):** 월 묶음과 월 소계 없이 `ul.tx-rows > li.tx-row` 평평한 목록. 행 왼쪽 날짜에 **연도 포함** `"2026년 3월 2일 (월)"`(여러 해가 섞이므로), 나머지는 날짜순 행과 같다.
   - 공통: 카테고리 이름·지출/수입 배지는 화면 제목과 같으므로 행에서 뺀다. 미래 날짜 거래도 그대로 보인다(OQ-H7). 행은 버튼 하나(`.tx-edit`), 삭제 버튼은 두지 않는다(OQ-H5).
5. **더 보기:** `nextCursor` 가 있으면 목록 아래 `"더 보기 (30/120)"` 버튼(`button.btn--ghost`, 숫자는 불러온 건수/전체 건수). 누르면 **같은 `sort`**, `limit=30`, 받은 커서로 다음 쪽을 불러 이어 붙인다(날짜순에서 같은 달이면 그 달 묶음에 이어 붙임). 불러오는 동안 버튼 비활성·`aria-busy`. 끝까지 불러오면 버튼을 없앤다.

### 6.4 데이터 흐름
- 패널에 들어올 때마다(`tabchange` → `history`) 정렬을 **최신순으로 되돌리고** 첫 쪽을 다시 받는다(선택한 정렬은 저장하지 않음, 다른 화면에서 저장·삭제·이름 변경이 있었을 수 있음).
- **정렬 변경:** 이미 눌린 정렬을 다시 누르면 아무 일도 없다. 다른 정렬을 누르면 `aria-pressed` 를 바꾸고, 진행 중인 요청(첫 쪽·더 보기)의 응답을 버리도록 순번을 올리고, 불러온 목록·커서를 비운 뒤 **커서 없이** 그 정렬의 첫 쪽을 부른다. 받은 목록으로 `#hist-list` 를 통째로 바꾼다. 포커스는 누른 정렬 버튼에 남긴다. 화면 맨 위로 스크롤하지 않는다.
- 늦게 온 응답은 버린다(기존 `seq` 방식, `record.js:580-597` 와 같은 패턴). 정렬 변경·더 보기 중에 패널을 나가면 그 응답도 버린다. 커서는 그 커서를 받은 정렬과 함께 보관해, 다른 정렬로 커서를 보내는 일이 없게 한다(5.2 의 400 은 정상 흐름에서 나오지 않아야 한다).
- `categorieschanged` 이벤트가 오면 선택을 지운다(이름 변경으로 옛 이름이 사라질 수 있음). 다음에 `#history` 로 오면 6.2 규칙대로 기록 탭으로 간다.
- 카테고리 이름·메모는 `textContent` 로만 넣는다(api.md 3A.1 규칙 3). 인라인 `style` 속성·`<style>`·인라인 스크립트 없음(CSP).

### 6.5 빈 상태·오류
- 거래 0건: 요약 카드·정렬 선택·목록 대신 `p.hint.empty-line` `"아직 이 카테고리 기록이 없어요"`.
- 첫 쪽 실패(들어올 때·정렬 변경 때): `p.error-text[role=alert]` 에 서버 메시지 + `"다시 시도"` 버튼(카테고리 관리 `#catm-retry` 와 같은 모양). 다시 시도는 지금 눌린 정렬로 부른다. 정렬 버튼은 계속 누를 수 있다.
- 더 보기 실패: 이미 불러온 목록은 그대로 두고 더 보기 버튼 아래에 오류 문구, 버튼은 다시 누를 수 있게 둔다.
- 401 은 기존 공통 처리(로그인 화면으로)를 따른다.

### 6.6 행을 눌렀을 때 (F-H5)
- 기록 탭의 기존 수정 흐름을 그대로 쓴다: `#record` 로 이동한 뒤 `startEdit(tx)`(지금은 모듈 내부 함수라 export 하거나 `CustomEvent('edittx', { detail: tx })` 로 넘긴다. 둘 중 frontend 가 정한다).
- 순서: 해시를 `#record` 로 바꾸고 패널이 보인 다음 `startEdit` 를 부른다(숨은 패널에서 `scrollIntoView`·`focus` 가 실패하지 않게).
- 수정 저장 뒤에는 기존 동작 그대로 기록 탭에 남는다(이력으로 자동 복귀 없음, OQ-H4). 기록 목록은 보고 있던 달 그대로다.
- 사용 안 함 카테고리 거래도 기존 "사용 안 함 칩" 처리로 고칠 수 있다(`record.js:170` 근처, api.md 4.3 예외).

### 6.7 비활성 카테고리·"그 외 N개"·수입
- **사용 안 함 카테고리:** 이력은 똑같이 보인다(서버가 문자열로만 찾음). 제목 옆 배지만 다르다.
- **"그 외 N개":** 진입점 A(`#month-summary`)는 묶지 않으므로 해당 없음. 대시보드 진입(나중)에서는 묶음 행을 누를 수 없게 둔다(12장).
- **수입 카테고리:** 같은 기능을 쓴다(OQ-H6). 진입점은 `"카테고리별 수입"` 블록. 정렬 4종도 같다.

### 6.8 접근성·반응형·테마 (F-H6)
- 랜드마크: `section#panel-history` `aria-labelledby="hist-title"`. 날짜순의 월 머리는 `h3`(목록 카드 제목 `h2` "기록 목록"은 시각적으로 숨김 가능).
- 정렬 그룹: `role="group"` `aria-label="정렬"`, 각 버튼 `aria-pressed`, 높이 44px 이상, 키보드 Tab·Enter·Space. 정렬이 바뀌고 첫 쪽을 받으면 `role="status"` 에 `"금액 큰순으로 정렬했어요. 120건"` 처럼 알린다.
- 목록 카드에 지금 정렬을 알리는 숨김 캡션(예: `"금액 큰순, 120건 중 30건"`)을 둔다.
- 더 보기 결과: `role="status"` 문구 `"30건 더 불러왔어요. 120건 중 60건"`. 포커스는 더 보기 버튼에 남기고, 끝까지 불러와 버튼이 사라지면 새로 붙은 첫 행 버튼으로 옮긴다(포커스가 `body` 로 가지 않게).
- 행 버튼 이름: `"{날짜(금액순이면 연도 포함)} {메모 또는 메모 없음} {금액} 수정"`.
- 금액은 tabular 숫자, `white-space: nowrap`. 긴 카테고리 이름(15자)은 제목에서 줄바꿈 허용, 메모는 한 줄 말줄임. 금액순 행의 연도 포함 날짜가 360px 에서 메모와 겹치지 않게 날짜 칸 너비를 고정하거나 두 줄(날짜 위·메모 아래)로 둔다.
- 360px(모바일 터치)·768px(`.screen` 최대 480px 가운데) 모두 같은 한 열 배치. 가로 스크롤 없음.
- 라이트·다크: 기존 토큰만 쓴다. `style.css`·JS 에 hex·rgb 색 금지(C-D6), `tokens.css`·`components.css` 수정 금지(C-D1).

## 9. 완료 기준 (QA 체크리스트)

별도 표시가 없으면 360px·768px, 라이트·다크에서 확인한다. 테스트 데이터에는 같은 금액 여러 건, 같은 날 여러 건, 같은 밀리초 `createdAt` 여러 건, 여러 해에 걸친 거래를 넣는다.

**API: 기본**
- [ ] C-H1. `GET /api/category-history?type=expense&category=식비`(sort 없음)가 `sort: "date_desc"` 로 세션 사용자의 식비 지출만 `date desc, createdAt desc, id desc` 로 돌려주고, `total`·`count`·`firstDate`·`lastDate`·`months` 가 같은 데이터로 직접 계산한 값과 같다. `count` 가 `GET /api/categories` 의 식비 `usedCount` 와 같다.
- [ ] C-H2. 격리: 다른 사용자가 같은 이름 "식비" 거래를 가지고 있어도 결과에 0건 섞인다. 수입 "기타"와 지출 "기타"가 섞이지 않는다.
- [ ] C-H3. 사용 안 함 카테고리, 카테고리 목록에 없는 이름 모두 200. 없는 이름은 빈 결과(`months: []`, `firstDate: null`, `nextCursor: null`). 카테고리 행이 0개인 사용자에게 호출해도 `categories` 행이 생기지 않는다.
- [ ] C-H4. 400: `type` 없음·잘못됨(`fields.type`), `category` 없음·빈 문자열·51자·제어문자(`fields.category`), `sort` 빈 값·`price`·`DATE_DESC`(`fields.sort`), `limit` 0·101·`1.5`·`abc`(`fields.limit`), `cursor` 깨진 값·`s` 가 4종 밖·금액순 커서에 `a` 없음(`fields.cursor`). 401 세션 없음. POST/PUT/DELETE 는 405 `Allow: GET`. 응답 헤더는 1장 공통 규약.

**API: 정렬**
- [ ] C-H6. 순서: 정렬 4종 각각 전체를 한 번에(`limit=100`, 100건 이하 데이터) 받은 순서가 5.1 정렬 표의 ORDER BY 로 직접 정렬한 결과와 같다. `date_asc` 는 `date_desc` 를 정확히 뒤집은 순서다.
- [ ] C-H7. 동점: 같은 금액 여러 건은 `amount_desc`·`amount_asc` 모두 날짜 최신 먼저, 같은 날짜면 `createdAt` 최신 먼저, 그것도 같으면 `id` 내림차순이다. 같은 요청을 3번 보내도 순서가 같다.

## 12. 나중 (이번 범위 아님)

- 대시보드 도넛 범례 행·카테고리 관리 "기록 N건"에서 이력 열기("그 외 N개" 묶음 행은 누를 수 없게, 묶인 카테고리는 표로 보기·관리 화면으로).
- 기간 선택, 메모 검색, 이력 안 월별 막대 차트, 선택한 정렬 기억.
- 수정 저장 뒤 이력 화면으로 돌아오기, 이력 안 삭제.
- 거래가 매우 많아지면 `(user_id, type, category, …)` 인덱스(운영 마이그레이션 필요).
