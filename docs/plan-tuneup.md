# 작은 개선 3건 계획서 (plan-tuneup v1)

작성: planner / 작성일: 2026-11-09 / 기준 커밋 `8c17220`
관련 문서: `docs/plan-category-history.md`(이력 화면, 12장 "나중"), `docs/plan-spring.md`(출렁임)

표기: **[사실]** 코드에서 확인한 내용(파일:줄), **[권장]** planner 기본값(사용자 확인 대상은 6장).

## 1. 목표

이력 화면의 정렬 전환을 깔끔하게 만들고, 대시보드·카테고리 관리에서도 이력으로 바로 가게 하며, 스크롤 출렁임을 작은 스크롤에는 반응하지 않는 묵직한 느낌으로 바꾼다.

## 2. 사용자 스토리

- 사용자로서 정렬을 바꿨을 때 이전 정렬 목록이 잠깐 보여서 헷갈리지 않았으면 한다.
- 사용자로서 대시보드 도넛 범례나 카테고리 관리 화면에서 카테고리를 눌러 바로 사용 이력을 보고, 뒤로 가면 원래 화면으로 돌아오고 싶다.
- 사용자로서 글을 읽듯 천천히 스크롤할 때는 화면이 출렁이지 않고, 빠르게 크게 넘길 때만 묵직하게 한 번 따라오는 느낌이면 좋겠다.

## 3. 범위 / 범위 밖

**범위:** 아래 T1~T3. 모두 frontend 만 바뀐다. **백엔드·API·DB 변경 없음**(이력 API `GET /api/category-history` 는 이름 문자열만 받으므로 그대로 쓴다).

**범위 밖**
- 기록 탭 달 이동 때 이전 달 목록이 남는 같은 종류의 문제(`record.js:591-603`, 요청 범위 밖).
- 스켈레톤 UI 새로 만들기, 정렬 전환 애니메이션, 새 색 토큰, `tokens.css`·`components.css` 수정.
- 대시보드 추이 차트·인사이트에서의 진입, "그 외 N개" 묶음 행에서의 진입.
- 출렁임 유닛 목록(`UNITS`) 변경, 출렁임 상한(YMAX)·늘어남(SMAX) 변경(6장 Q3 에서 원하면 별도).

### T3. 스크롤 출렁임: 단단하고 묵직하게, 큰 스크롤에만

**현재 동작**
- [사실] `SPRING` k 170, c 14 → ω = √170 ≈ 13.0 rad/s(2.1Hz), ζ = 14 / (2·13.0) ≈ 0.54, 되튐 ≈ e^(−πζ/√(1−ζ²)) ≈ 13%(`lib/spring.js:7-8`).
- [사실] 끌림 주입은 프레임마다 `y += Δ × dragRatio(d)` 이고 속도 문턱이 없다(`lib/spring.js:51-55`, `scroll-spring.js:160`). 기준점에서 500px(R) 이상 떨어진 행은 비율 1 이라 **한 프레임에 12px(행 상한)만 스크롤해도 상한까지 밀린다.** 그래서 천천히 읽는 스크롤에도 늘 출렁인다(= "물결처럼 가볍게").

**변경안 [권장 값]**

1. 스프링: 고유 진동수를 낮추고(묵직, 느리게 돌아옴) 감쇠비를 올린다(단단, 되튐 거의 없음).

| 값 | 현재 | 변경 | 근거 |
|---|---|---|---|
| `k` | 170 | **90** | ω = √90 ≈ 9.49 rad/s(1.5Hz). 같은 변위에서 돌아오는 움직임이 약 1.37배 느림(13.0/9.49) |
| `c` | 14 | **15** | ζ = 15 / (2·9.49) ≈ 0.79 → 되튐 ≈ e^(−π·0.79/0.61) ≈ **1.7%**(현재 13%). 감쇠 속도 ζω = 7.5/s 로 현재(7.0/s)와 비슷해 **정지 시간은 늘지 않음**: 20px 에서 정지(0.15px) 까지 약 0.7s 추정, 기존 800ms 기준 안 |

2. 속도 문턱(작은 로직 추가): 스크롤 속도가 느리면 끌림을 주입하지 않는다.
   - `lib/spring.js` 에 순수 함수 `speedGain(speed)` 추가: `speed = |Δ| / dt`(px/s). `VMIN` 이하 0, `VFULL` 이상 1, 사이는 smoothstep(t²(3−2t)) 곡선(문턱 근처에서 갑자기 튀지 않게).
   - `inject(state, delta, d, ymax, gain = 1)`: `y += Δ × dragRatio(d) × gain`(기본 1 이라 기존 호출·테스트 호환).
   - `scroll-spring.js` `frame`: 프레임마다 `gain = speedGain(|delta| / dt)` 을 한 번 계산해 모든 유닛에 같은 값으로 넘긴다(`dt` 는 이미 계산됨, 0 나누기 방지로 `max(dt, 1/240)`).
   - 새 설정값(`SPRING` 안):

| 값 | 권장 | 근거 |
|---|---|---|
| `VMIN` | **600** px/s | 천천히 읽는 트랙패드·손가락 스크롤(대략 100~400px/s)과 휠 한 칸(약 100px 를 0.15s 동안 = 약 670px/s)은 거의 0 |
| `VFULL` | **2000** px/s | 빠른 휠 연속·플링(2000~5000px/s)에서만 지금처럼 상한까지. 기존 e2e 의 휠(100px/16ms ≈ 6000px/s)·터치(40px/16ms ≈ 2500px/s) 시나리오는 1 이라 기존 기대값(행 최대 ≥6px 등) 유지 |

3. 바꾸지 않는 값: `R` 500, `YMAX_CARD` 20, `YMAX_ROW` 12, `VREF` 1200, `SMAX` 0.015, `HARD_STOP_MS` 1200 등. (상한을 키울지는 6장 Q3.)

**수정 파일:** `js/lib/spring.js`(값, `speedGain`, `inject` 인자), `js/scroll-spring.js`(gain 계산 한 줄과 전달), `src/frontend/test/spring.test.js`, `e2e/tests/spring.spec.js`(새 시나리오 추가), `docs/plan-spring.md` 에 값 변경 한 줄 기록(frontend).
