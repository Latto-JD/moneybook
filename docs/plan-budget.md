## 1. 목표

지출 카테고리마다 매달 같은 예산 금액을 정하고, 대시보드에서 기준 월의 카테고리별 사용액과 남은 금액을 바로 보게 한다.

## 2. 사용자 스토리

- 사용자로서 카테고리 관리에서 지출 카테고리에 월 예산을 정하고, 바꾸고, 지우고 싶다(휴대폰 숫자 패드로).
- 사용자로서 대시보드에서 "이번 달 이 카테고리에 얼마 남았나"와 "예산 전체로 얼마 남았나"를 한눈에 보고 싶다.
- 사용자로서 예산을 넘긴 카테고리를 색에 의존하지 않고 알아보고 싶다.

## 3. 범위 / 범위 밖

**범위**
- `categories.budget` 열(nullable) 추가. 색(v4.5) 마이그레이션과 같은 `schema.sql` 에 넣어 운영 마이그레이션은 **1회**.
- API: 카테고리 객체에 `budget`, `PATCH /api/categories/:id` 로 정하기·바꾸기·지우기(`null`).
- 카테고리 관리: 지출 활성 행에 "예산" 버튼과 인라인 입력, 행 메타에 예산 표시.
- 대시보드: 예산 카드(전체 합계 줄 + 카테고리별 진행 막대, 초과 표시).

**범위 밖**
- 월마다 다른 예산, 수입 예산, 알림·푸시, 결제수단·시각(#13).
- 예산 이월, 주간/일간 예산, 전체(카테고리 무관) 단일 예산.
- 인사이트(R4 등) 규칙 변경, 기록 탭에 예산 표시, 카테고리 추가 폼에서 예산 입력.
- 예산 카드에서 이력 열기, 새 모션 값(`lib/motion.js`), 새 API 엔드포인트.

## 4. 설계

### 4.1 DB (`src/backend/db/schema.sql`)

색 `alter`(현재 :62-63) **바로 뒤**에 추가한다. 백필 없음.

```sql
-- v6: 지출 카테고리 월 예산(원). null = 예산 없음. 매달 같은 값. 추가 전용, 재실행해도 아무 일도 하지 않는다.
alter table categories add column if not exists budget integer
  check (budget is null or budget between 1 and 100000000);
```

- 멱등: 색 마이그레이션과 한 번에 실행해도, 여러 번 실행해도 오류·변화가 없다. 기본 세트 insert·방어용 insert·색 update 는 `budget` 을 언급하지 않으므로 null 로 남는다.
- "지출만" 규칙은 DB check 가 아니라 API 에서 지킨다(다른 열을 참조하는 check 를 열 추가 구문에 넣지 않는다. PGlite·Postgres 동작 차이 위험을 피한다).
- 호환: 구버전 코드는 열을 몰라도 동작한다. 새 코드는 열이 없으면 카테고리 API 가 500 이므로 **마이그레이션 먼저**(색과 같다).

### 4.2 API (`docs/api.md` v4.6, backend 가 구현 전에 먼저 고친다)

추가할 절:
- **0G. v4.6 변경 요약**: 카테고리 `budget` 추가, PATCH `budget`, 스키마 `categories.budget`. 응답 필드 추가라 호환. 운영 마이그레이션 필요(색과 묶음).
- **3A.1** 카테고리 객체 표에 `budget` 행: 원 단위 정수(1~100000000) 또는 `null`(예산 없음). 수입 카테고리는 항상 `null`. 이름 변경·사용 안 함·다시 사용해도 유지(id 기준). 예시 JSON 에 `"budget": 400000` / `null` 추가. GET `items`, POST·PATCH 응답 모두 포함.
- **3A.3** POST: 본문 `budget` 은 무시하고 새 카테고리는 `null`.
- **3A.4** PATCH: 본문에 `budget` 허용. `name`·`active`·`color`·`budget` 중 1개 이상 필요(없으면 message "name, active, color, budget 중 하나는 보내 주세요."). 처리 순서 이름 → 상태 → 색 → 예산, 한 트랜잭션.
  - 형식 검증(400, 대상 조회 전): `budget` 이 `null` 또는 1~100000000 정수가 아니면(0, -1, 100000001, `"5000"`, `1.5`) `fields.budget` = "예산은 1원 이상 1억원 이하의 정수여야 해요."
  - 유형 검증(400, 대상 조회 404 **뒤**): 대상이 수입 카테고리인데 `budget` 이 `null` 이 아니면 `fields.budget` = "예산은 지출 카테고리에만 정할 수 있어요." 수입 카테고리에 `null` 은 200·변화 없음(멱등).
  - 같은 값이면 200·변화 없음. 사용 안 함 카테고리에도 정할 수 있다(API 는 막지 않는다. 화면은 버튼을 숨김).
  - 오류 형식은 기존 1.1 그대로: `{ "error": { "code": "VALIDATION_ERROR", "message": "<첫 사유>", "fields": { "budget": "<사유>" } } }`.
  - 검사 순서 문장 갱신: 입력 검증(400) → 대상 조회(404) → 금지 이름·수입 예산(400) → 이름 중복(409) → 마지막 활성(409) → 한도(409).
- **8.7 카테고리 예산 컬럼 (v4.6)**: 4.1 SQL, 멱등, "8.6 과 같은 실행으로 반영", 확인 쿼리(6장), 롤백(코드만 되돌림, DROP 안 함).
- 거래·집계·인사이트·이력 API 는 바뀌지 않는다. 대시보드는 기존 `GET /api/stats/categories?from=M&to=M&type=expense`(5.3)로 사용액을 계산한다.

### 4.3 카테고리 관리 화면 (예산 입력)

- **[권장] D1** 지출 **활성** 행의 동작 버튼에 "예산"을 추가한다. 순서 "색 · 예산 · 이름 바꾸기 · 사용 안 함". 수입 행·사용 안 함 행에는 없다. 접근 이름 "{이름} 예산 정하기" 또는 "{이름} 예산 바꾸기, 지금 {N}원".
- 누르면 그 행 아래에 인라인 입력 행이 열린다(이름 바꾸기와 같은 방식). 색 고르기·이름 바꾸기·예산 중 **한 번에 하나, 한 행**만 열린다.
  - 입력칸: `type="text"`, `inputmode="numeric"`, `enterkeyhint="done"`, `autocomplete="off"`, 라벨 "{이름} 월 예산(원)". 기존 `lib/money.js` `formatAmountInput`·`parseAmount` 로 쉼표 표시·해석. 현재 값이 있으면 채운 채로 열고 전체 선택.
  - 버튼 "저장", "취소". 안내 "비워 두고 저장하면 예산을 지워요" (`aria-describedby`).
  - Enter = 저장, Esc = 취소(조합 중 Enter 무시, 이름 바꾸기와 같음).
- 저장: 빈 칸이면 `PATCH {budget: null}`, 아니면 프론트 검증 후 `PATCH {budget: N}`. 진행 중 중복 요청 없음(`busy`).
  - 성공: 입력 행을 닫고 `#catm-status` 에 "'{이름}' 예산을 {N}원으로 정했어요" / "'{이름}' 예산을 지웠어요". 포커스는 그 행 "예산" 버튼(입력칸에서 포커스가 빠져 숫자 패드가 닫힌다). 목록을 다시 받고 `categorieschanged` 로 대시보드도 갱신.
  - 실패(프론트 검증 포함): 행 오류(`ui.rowError`), 입력칸 `aria-invalid`, 입력값 유지, 포커스는 입력칸.
- **[권장] D2** 행 메타: 예산이 있으면 "예산 {N}원 · 기록 N건", 없으면 지금처럼 "기록 N건". 이번 달 사용액은 여기서 보이지 않는다(추가 요청 없이 끝내기 위함. 사용액은 대시보드에서).
- 프론트 검증 문구(**[권장] D5**): 범위 밖·숫자 아님 → "예산은 1원 이상 1억원 이하의 숫자로 입력해 주세요" (`AMOUNT_RANGE_TEXT` 와 같은 형식).

### 4.4 대시보드 예산 카드

- **[권장] D3** 위치: 요약 카드(`#kpi`, `index.html:134`) 바로 아래 새 카드 `#budget-card`, 제목 "{기준 월 이름} 예산"(예: "이번 달 예산", `viewedMonthName` 재사용). 지출/수입 보기 전환과 무관하게 항상 지출 기준.
- 표시 대상: 활성 지출 카테고리 중 `budget` 이 있는 것. 하나도 없으면 카드 전체를 숨긴다.
- 사용액: 기준 월(`state.base`)의 `stats/categories` 지출 `items[].total` 을 이름으로 찾는다(없으면 0). 진행 중인 달의 미래 날짜 거래도 포함(미리 넣은 고정비도 예산을 쓴 것으로 본다). 지난 달을 보면 지금 예산 값과 비교한다(매달 같은 값이므로).
- **[권장] D4** 합계 줄(맨 위 1줄): "예산 {합계}원 중 {사용 합계}원 썼어요 · {남은}원 남음" 또는 "… · {초과}원 초과". 합계는 예산을 정한 카테고리만 더한다. 보조 문구 "예산을 정한 {k}개 카테고리 기준". 막대 1개 포함.
- 카테고리별 행: 견본(저장된 색·무늬) + 이름 + 막대 + "{사용}원 / {예산}원" + "{남은}원 남음" 또는 "{초과}원 초과". 정렬: 사용률 높은 순(초과가 위), 동률은 `sortOrder`, 이름.
- 막대: 채움은 카테고리 색·무늬(`data-viz` 기존 클래스), 100% 에서 멈춘다. 막대는 `aria-hidden`, 정보는 글자로 전달한다.
- **[권장] D6** 초과 표시: 사용 > 예산이면 행에 경고 아이콘 + "N원 초과" 글자(지출 의미 색 글자) + 막대 끝 굵은 테두리. 색만으로 표시하지 않는다. 80% 같은 "주의" 단계는 두지 않는다. 사용 = 예산은 "0원 남음"(초과 아님).
- 목록은 `<ul>`, 행 접근 이름 예: "식비, 40만원 중 32만원 사용, 8만원 남음" / "카페/간식, 10만원 중 12만원 사용, 2만원 초과".
- 불러오기: 대시보드에 `budget` 요청 종류를 추가한다(자기 순서 번호, `failures` 에 '예산' 실패 문구, 다시 시도 대상). 지출 보기일 때도 기존 `loadCat` 응답을 재사용하지 않고 따로 받는다(보기 전환과 독립, 단순). 예산이 하나도 없으면 요청하지 않는다. `categorieschanged`·달 이동·탭 진입 때 다시 그린다. 새 모션은 없다.

## 6. 운영 반영 절차 (사용자 직접, 색과 묶어 1회)

연결 문자열·`.env.production.local` 내용은 채팅에 붙여넣지 않는다. 색 계획(`plan-category-color.md` 6장)의 절차를 **대체**한다(색만 따로 하지 않는다).

1. R1 "머지 가능"까지 로컬에서 끝낸다. `08d1502`(색)와 예산 커밋을 아직 푸시하지 않는다.
2. Neon 콘솔에서 **백업 브랜치**를 만든다. 실행 전 기록: `select count(*), sum(amount) from transactions;`, `select count(*) from categories;`.
3. `vercel env pull .env.production.local --environment=production`. Neon Connect 창에서 **default 브랜치**, **Connection pooling 끔**(`-pooler` 없음) 확인.
4. `npm run db:migrate:prod -- --yes` → 출력 `마이그레이션 완료 (driver=pg, …)` 확인.
5. Neon SQL 편집기에서 **default 브랜치를 골라** 실행하고 숫자를 메인에 알려 준다("확인했어"만으로는 진행하지 않는다).
   ```sql
   select column_name, data_type from information_schema.columns
    where table_name = 'categories' and column_name in ('budget', 'color') order by column_name;
   select count(*) as total, count(*) filter (where color is null) as nulls,
          count(*) filter (where color between 1 and 12) as ok,
          count(*) filter (where budget is not null) as budgets from categories;
   select count(*), sum(amount) from transactions;
   ```
   기대값: 첫 쿼리 2행(`budget integer`, `color smallint`). 둘째 `nulls = 0`, `ok = total`, `budgets = 0`. 셋째와 categories 행 수가 2번 기록과 같다.
6. 푸시(Vercel 배포).
