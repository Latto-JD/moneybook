# 화면 정리 계획서: 정렬·간격·높이 통일 (plan-redesign v1)

작성: planner / 작성일: 2026-10-23 / 기준: 현재 작업 트리(후속 2단계 반영: 되돌리기 토스트, 남은 돈 비율, 수입 인사이트, 해·달 아이콘 버튼)
시안(사용자 승인, 읽기 전용): scratchpad `design-canvas/project/` 의 `Main.dc.html`(기록, theme 값으로 다크·라이트), `Dashboard.dc.html`, `Account.dc.html`. 같은 폴더의 `RecordLight.dc.html` 은 `Main.dc.html` 의 라이트 값과 같아서 따로 다루지 않는다.
관련 문서: `docs/plan-design.md`(C-D1 원본 유지 규칙), `docs/plan-followup.md`(13장 2단계), `docs/api.md`

표기: **[사실]** 은 코드·시안에서 확인한 내용(파일:줄), **[권장]** 은 planner 권장 기본값. 열린 질문(13장)의 답이 없으면 권장값으로 진행한다.

## 1. 목표

사용자가 말한 문제("정렬이 깔끔하지 않고 조잡해 보임, 편의성과 깔끔함")를 승인된 시안대로 고친다. 기능은 지금 그대로 두고 프론트만 바꾼다. 좌우 정렬선 하나, 같은 높이·모서리, 요약 카드 1개로 기록·대시보드·내 정보 화면을 정리한다.

## 2. 사용자 스토리

- 사용자로서 화면의 왼쪽 끝이 한 줄로 맞아서 정돈되어 보이기를 바란다.
- 사용자로서 이번 달 남은 돈·수입·지출을 카드 한 장에서 한눈에 보고 싶다(금액이 두 줄로 깨지지 않게).
- 사용자로서 카테고리를 옆으로 넘기지 않고 한 화면에서 고르고 싶다.
- 사용자로서 헤더에서 실수로 로그아웃을 누르지 않고, 로그아웃은 내 정보 화면에서 하고 싶다.
- 사용자로서 대시보드에서 카테고리별 지출과 알림을 정렬된 목록으로 읽고 싶다.

## 3. 범위 / 범위 밖

**범위**
- 공통: 좌우 20px 정렬선, 높이 44/48/52, 모서리(카드 20·입력/버튼 14·칩 12), 카드 테두리, 금액 tabular 숫자.
- 헤더: 이름(›) + 해·달 버튼만. 로그아웃은 내 정보 화면 아래로 옮긴다.
- 기록: 요약 카드 1개, 폼의 카드 겹침 제거, 간격 12/10, 빠른 금액 3칸, 카테고리 4열 격자, 메모 placeholder, 날짜 캡션을 제목 오른쪽으로.
- 대시보드: 제목 + 월 이동 알약, 요약 카드, 카테고리별 지출 행, 인사이트 카드 목록.
- 내 정보: 뒤로, 계정 카드(이메일), 이름 입력 + 저장 한 줄, 아래쪽 로그아웃 외곽선 버튼.
- 카테고리 관리·로그인 화면: 공통 높이·모서리가 적용되는지 확인만 한다(구조는 바꾸지 않음).

**범위 밖**
- 3단계 바텀시트, 4단계 월 예산·결제수단·시각, 새 API·DB 변경(**백엔드 변경 없음**, `docs/api.md` 변경 없음).
- 시안의 "가입일"(서버에 값이 없음, OQ-R11), 시안의 Noto Sans KR 글꼴(Pretendard 유지), 새 색 토큰.
- `tokens.css`·`components.css` 수정(C-D1 원본 유지 규칙. 바꿀 것은 `style.css` 에서 덮어쓴다), `src/frontend/office/`, `design_handoff_moneybook/`, 시안 파일 자체.
- 카테고리 관리 화면 재배치, 로그인 화면 재배치, 하단 탭 높이 변경(`--tabbar-h` 64 유지), 카드 순서를 사용자가 바꾸는 기능, 애니메이션 추가.

## 6. 금액이 깨지지 않게 (요약 카드)

- 360px 에서 카드 안 너비는 360 − 40 − 40 = 280px, 2열이면 열마다 약 128px(구분선·간격 제외)다. `수입` + `100,000,000원`(15px 600)은 한 줄에 들어가지 않을 수 있다.
- 규칙: 각 칸은 `라벨 | 금액` 을 한 줄에 두되 `flex-wrap: wrap`. 금액은 `white-space: nowrap; margin-left: auto`. 모자라면 금액이 라벨 아래 줄로 내려가고 오른쪽 정렬된다. 금액 글자 자체는 나뉘지 않는다.
- 남은 돈 줄도 같다: `이번 달 남은 돈` 과 `−100,000,000원`(28px)이 한 줄에 안 들어가면 두 줄.
- 어떤 경우에도 가로 스크롤·잘림·말줄임으로 금액을 숨기지 않는다. 확인할 값: 0원, 877,530원, 100,000,000원, 999,999,999원(월 합계는 한 거래 1억을 넘을 수 있음), 음수.

## 8. 카테고리 격자 (8개 초과, 최대 30개)

- 4열 격자, 칸 너비는 같다(`repeat(4, minmax(0, 1fr))`, 간격 8). 순서는 지금처럼 사용자 `sortOrder`.
- **[권장] 접기:** 활성 카테고리가 8개 이하면 모두 보인다. 9개 이상이면 처음 7개 + 8번째 칸에 `더 보기 (N)` 버튼(`aria-expanded="false"`, `aria-controls` 격자)을 둔다. 누르면 전부 펼치고 맨 끝 칸이 `접기` 가 된다. 펼침 상태는 유형(지출/수입)별로 기억하고 새로고침하면 접힌다.
- 선택된 카테고리가 접힌 부분에 있으면(자동완성·빠른 입력·거래 수정으로 고른 경우) **자동으로 펼친다**. 선택이 화면에서 사라지지 않는다.
- 사용 안 함 카테고리 칩(거래 수정 중)은 항상 보이는 마지막 칸에 붙는다(접힘과 상관없이).
- 이름: 칸 안에서 최대 **2줄**까지 줄바꿈(`line-clamp: 2`), 칸 높이는 44 이상으로 늘어난다. 2줄로도 넘치면 말줄임. 버튼 글자는 전체 이름이라 접근 이름에는 잘리지 않은 이름이 들어간다. 시각적으로 잘린 경우 `title` 로 전체 이름(OQ-R3). 360px 칸 너비 약 74px.
- 키보드: Tab 순서는 격자 순서, `더 보기`/`접기` 를 누른 뒤 포커스는 그 버튼 자리(펼친 뒤에는 8번째 카테고리로)에 둔다. 선택 칩 Enter 저장(C29)은 그대로.
- 30개면 펼친 격자는 8줄(약 400px). 저장 버튼이 sticky 라 입력 흐름은 막히지 않는다.
- 순수 함수로 뺀다: `lib/category-grid.js` 의 `gridView(names, selected, expanded, limit = 8)` → `{ visible, hiddenCount, toggle: null | 'more' | 'less' }` + 단위 테스트(0·1·8·9·30개, 선택이 숨은 부분, 사용 안 함 칩).

## 9. 접근성

- 포커스 순서 = 화면 순서. 헤더(이름 → 해·달) → 제목 → 요약 → 폼(종류 → 금액 → 초기화 → 빠른 금액 → 편집 → 카테고리 → 더 보기 → 메모 → 날짜 → 저장).
- 모든 누르는 요소 44×44 이상, 포커스 링(`--shadow-focus`)이 카드 테두리·sticky 후광에 가려지지 않는다.
- 메모·이름 등 placeholder 만 보이는 입력은 `<label>`(시각적으로 숨김)을 유지하고, placeholder 대비는 지금 토큰(`--color-text-muted`, 4.5:1 이상).
- 요약 카드: 읽는 순서 남은 돈 → (비율) → 수입 → 지출. 금액 요소의 `aria-label`(예: `이번 달 수입 0원`) 유지. 색 외에 아이콘·글자로 수입/지출 구분.
- 카테고리 행: 막대는 장식(`aria-hidden`), 금액·% 는 글자로 읽힌다. 표 대체 유지.
- 인사이트 장식 아이콘 `aria-hidden`, 문장은 글자 그대로(XSS 규칙 C61 유지).
- 로그아웃이 헤더에서 사라지므로 내 정보 진입 경로(헤더 이름 링크)는 접근 이름에 "내 정보" 뜻이 들어가야 한다. 지금 이름 링크 접근 이름 규칙을 확인하고, 없으면 `aria-describedby` 로 "내 정보 열기" 를 붙인다.
- 대비: 라이트·다크 모두 글자 4.5:1, 테두리·막대·아이콘 3:1 이상.

## 10. 360px · 768px

- 360: 위 6장·8장 규칙. 가로 스크롤 0. 헤더 한 줄(이름 칸 40px 초과 기존 C-T9 기준). 대시보드 제목 줄: h1(약 100px) + 월 알약(44 + 약 92 + 44 = 약 180px)이 280~320px 안에 들어간다. 모자라면 알약이 제목 아래 줄로 내려간다(겹침 없음).
- 768: `.screen` 최대 너비 480 가운데 정렬 그대로. 같은 규칙으로 넓어질 뿐 열 개수는 바꾸지 않는다(카테고리 4열, 요약 2열).
- 라이트·다크 각각, OS 다크 + 저장값 없음 포함.
