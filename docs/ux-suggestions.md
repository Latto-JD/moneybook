작성: planner / 작성일: 2026-11-17 / 기준: `af0e339`(튠업) 작업 트리
전제: 사용자 1명(본인), 주로 휴대폰. 재디자인·모션·출렁임(값 유지)·카테고리 사용 이력은 만족 → 손대지 않는다.

## 우선순위 상

### U1. 지난 날짜로 넣으려면 탭이 많다
- **문제:** 어제 쓴 돈을 넣으려면 "날짜: 오늘" 펼치기 → 날짜 칸 → 네이티브 달력에서 고르기로 3번 이상 눌러야 한다. 근거 `index.html:75-80`(`<details>` + `input type=date`), `lib/date.js:75-81`(요약 글자도 "오늘" 외에는 "11월 16일 (월)" 뿐, "어제" 표현 없음).
- **제안:** 날짜 줄을 접지 않고 칩 3개 `오늘 · 어제 · 다른 날…` 로 둔다. "다른 날…" 만 지금의 날짜 칸을 연다. 요약 글자에 "어제" 를 추가한다. 되돌리기·초기화(`reset.js`) 규칙은 그대로.
- **크기:** S / **BE:** 아니오 / **DB:** 아니오

### U2. 목록에서 거래를 고치면 보던 자리를 잃는다
- **문제:** 목록 행을 누르면 화면 맨 위 입력 폼으로 튀고(`record.js:380` `scrollIntoView`), 저장·취소 뒤에도 폼에 남는다. 목록 아래쪽 거래를 여러 개 고치려면 매번 다시 스크롤해야 한다.
- **제안:** 수정을 저장하거나 취소하면 고쳤던 행(같은 id, 없으면 그 날짜 묶음)으로 스크롤을 돌려주고 잠깐 강조한다. 근본 해결은 3단계 바텀시트(`plan-followup.md` 7.2)이며, 이것은 그 전의 작은 대안이다. 바텀시트를 곧 할 거라면 생략.
- **크기:** S (바텀시트는 L) / **BE:** 아니오 / **DB:** 아니오

### U3. 삭제만 브라우저 확인창이고, 지운 뒤에는 되돌릴 수 없다
- **문제:** 저장·수정은 토스트 [되돌리기]가 있는데 삭제는 `window.confirm`(`record.js:570`)이라 모양이 다르고 한 번 더 눌러야 하며, 잘못 지우면 복구가 안 된다. 카테고리 "사용 안 함"도 같은 확인창이다(`category-manager.js:217`).
- **제안:** 거래 삭제는 확인창 없이 바로 지우고 "삭제했어요 [되돌리기]"(5초, 기존 토스트 규칙) 를 띄운다. 되돌리기는 지운 값으로 `POST` 재생성(새 id·createdAt 이 되어 같은 날짜 안 순서가 바뀔 수 있음 — 사용자 수용 여부 확인). 서버 소프트 삭제 방식은 DB 변경이 필요해 권하지 않는다. `plan.md:96` "삭제 실행 취소 제외" 결정을 바꾸는 것이다.
- **크기:** M / **BE:** 아니오(재생성 방식) / **DB:** 아니오

### U4. 휴대폰 홈 화면에 앱처럼 둘 수 없다
- **문제:** 웹 앱 manifest·`apple-touch-icon` 이 없다(`src/` grep 0건, `index.html:8` 은 svg 파비콘만). 매번 브라우저를 열고 주소창·탭바가 화면 높이를 먹는다(740px 폰에서 이미 공간이 빠듯함, `improvements.md` A1).
- **제안:** `manifest.webmanifest`(이름, `display: standalone`, 테마색 라이트/다크, 아이콘 192/512 PNG)와 `apple-touch-icon` 추가. 오프라인 캐시(service worker)는 이번 범위 밖으로 둔다(데이터 정합성 문제).
- **크기:** S / **BE:** 아니오(정적 파일. `vercel.json` 에 manifest MIME 이 필요하면 한 줄) / **DB:** 아니오

## 우선순위 중

### U5. 거래 목록까지 스크롤이 길다
- **문제:** 기록 탭에서 이번 달 거래를 보려면 요약 카드 → 입력 폼 → 빠른 입력 → "카테고리별 수입" → "카테고리별 지출" 막대를 모두 지나야 한다(`record.js:493-496` 이 목록 앞에 두 블록을 그림, `index.html:93-102`).
- **제안:** 두 카테고리 블록을 하나의 접힘 영역 "카테고리별 보기"로 묶어 기본은 접고, 펼침 상태를 기억한다. 막대 행 → 이력 진입은 그대로. (대안: 거래 목록을 카테고리 블록보다 위로.) 사용자에게 두 안 중 고르게 한다.
- **크기:** S / **BE:** 아니오 / **DB:** 아니오

### U6. 불러오기에 실패하면 새로고침밖에 없다
- **문제:** 기록 탭 월 데이터 실패는 오류 글자만 보인다(`record.js:605`). 대시보드는 4개 요청 중 **마지막 실패 문구 하나만** 남고(`dashboard.js:74`) 다시 시도 버튼이 없다. 인사이트도 글자만(`insights.js:41`). 이력·카테고리 관리에는 이미 "다시 시도"가 있다(`index.html:167, 200`).
- **제안:** 기록 월 카드·대시보드 상단에 이력 화면과 같은 "다시 시도" 버튼을 둔다. 대시보드는 실패를 모아 "일부를 불러오지 못했어요" 한 줄 + 다시 시도(실패한 요청만)로 보인다. 저장 실패는 입력이 남아 있어 지금도 괜찮다(`record.js:349-351`).
- **크기:** S / **BE:** 아니오 / **DB:** 아니오

### U7. 카테고리 순서를 바꿀 수 없다
- **문제:** 화면은 "목록 순서대로 차트의 색과 무늬가 정해져요"라고 안내하지만(`index.html:163`) 순서를 바꾸는 방법이 없다. 서버도 PATCH 의 `sortOrder` 를 무시한다(`api.md:319`). 입력 격자는 앞 7칸만 보이므로(`category-grid.js` GRID_LIMIT) 자주 쓰는 새 카테고리는 늘 "더 보기"를 한 번 더 눌러야 한다.
- **제안:** 카테고리 관리 행에 "위로 / 아래로" 버튼(드래그보다 터치·스크린리더에 안전). 서버는 순서 변경 API(예: `PUT /api/categories/order` 유형별 id 배열) 추가. `sort_order` 컬럼은 이미 있다(`api.md:594`). 색·무늬가 바뀐다는 점을 화면에 알린다.
- **크기:** M / **BE:** 예(api.md 먼저) / **DB:** 아니오

### U8. 메모로 지난 거래를 찾을 수 없다
- **문제:** 기록 목록은 월 이동만 있다(`index.html:94-98`). "지난번 병원비 얼마였지" 는 카테고리 이력(전 기간)으로만 찾을 수 있고 메모 검색은 없다.
- **제안:** 이력 화면 패턴을 재사용한 "검색" 화면(메모 포함 검색, 전 기간, 최신순, 30건 더 보기). 서버에 검색 API 추가(메모 `ILIKE`). 인덱스 없이도 1인 데이터량이면 충분하다 **[추측]**.
- **크기:** M~L / **BE:** 예 / **DB:** 아니오

### U9. 내 정보에서 이메일이 잘리고 터치로는 전체를 볼 수 없다
- **문제:** 이메일이 말줄임(`style.css:339`)이고 전체 값은 `title` 툴팁뿐(`account.js:16`). 휴대폰에서는 툴팁이 뜨지 않는다. `improvements.md` B2 에서 제안했지만 아직 반영되지 않았다.
- **제안:** 이 화면의 이메일만 말줄임 대신 줄바꿈(`overflow-wrap: anywhere`). 헤더는 그대로.
- **크기:** S / **BE:** 아니오 / **DB:** 아니오

### U10. 비밀번호 변경·계정 삭제가 없다
- **문제:** 내 정보에는 이름과 로그아웃만 있다(`index.html:230-252`). 비밀번호를 바꾸려면 방법이 없고, 비밀번호를 잊으면 복구 수단도 없다(메일 발송 없음).
- **제안:** (a) 비밀번호 변경(현재 비밀번호 확인 + 새 비밀번호, 다른 세션 종료)을 먼저. (b) 계정 삭제는 `improvements.md` C1 그대로(사용자 1명이라 급하지 않음). 비밀번호 찾기(메일)는 범위 밖.
- **크기:** (a) M, (b) L / **BE:** 예 / **DB:** 아니오(외래 키 cascade 확인 필요)

## 우선순위 하

### U11. 로그인이 만료되면 입력 중이던 내용이 사라진다
- **문제:** 401 이 오면 바로 로그인 화면으로 이동한다(`api.js:117-120`). 세션은 30일(`config.js:24`)이라 드물지만, 만료 직후 저장을 누르면 쓰던 금액·메모가 없어진다.
- **제안:** 이동 전에 입력 초안(종류·금액·카테고리·메모·날짜)을 `sessionStorage` 에 두고, 다시 로그인하면 폼에 채워 "로그인 전에 쓰던 내용을 채웠어요"를 보인다. 또는 사용할 때마다 만료를 연장(슬라이딩)한다 — 이쪽은 BE.
- **크기:** S / **BE:** 아니오(초안 보존) · 예(슬라이딩) / **DB:** 아니오

### U12. 글자 크기가 휴대폰 설정을 따르지 않을 수 있다
- **문제:** 글자 크기 토큰이 모두 px 고정이고 최소 12px 이다(`tokens.css:71-75`). iOS 의 글자 크기 설정이 반영되지 않는다 **[추측: 실제 기기 미확인]**. 보조 글자(13px, 회색)가 많은 화면(이력 날짜·인사이트 섹션 제목)은 밖에서 읽기 어렵다.
- **제안:** 먼저 실제 폰에서 시스템 글자 크게 설정으로 확인한다. 반영이 안 되면 토큰을 rem 으로 바꾸고 360px 레이아웃 회귀를 본다. 출렁임·모션 값은 건드리지 않는다.
- **크기:** M / **BE:** 아니오 / **DB:** 아니오

### U13. 스크린리더·키보드 잔여 거슬림 (묶음)
- **문제·근거:**
  1. 카테고리 관리 이력 버튼의 접근 이름이 보이는 글자와 순서가 다르다: 보이는 글자 "식비 / 기록 21건", 이름 "식비 사용 이력 보기, 기록 21건"(`category-manager.js:60`). 음성 조작에서 보이는 글자로 부르기 어렵다(WCAG 2.5.3).
  2. 대시보드 요약 카드가 `aria-live="polite"`(`index.html:117`)라 탭에 들어올 때·달을 바꿀 때마다 카드 전체를 읽는다.
  3. 저장 직후 [되돌리기]까지 Tab 약 15회(토스트가 저장 버튼 바로 앞 DOM 에 있음, `record.js:107-112`). 휴대폰 터치에는 영향 없음.
  4. 대시보드 재렌더 때 포커스 유실(이전 리뷰 미룬 권장, 재현 경로는 이번에 확인하지 않음).
- **제안:** 1 은 이름을 "식비 기록 21건, 사용 이력 보기" 로. 2 는 live 를 빼고 달 이름 제목만 알린다. 3 은 저장 후 상태 알림에 "되돌리려면 …" 안내를 넣거나 그대로 둔다(휴대폰 위주라 낮음). 4 는 frontend 가 재현 후 판단.
- **크기:** S / **BE:** 아니오 / **DB:** 아니오

## 참고: 이미 계획된 큰 기능 (이 목록에서 다시 쓰지 않음)
- 3단계 바텀시트(거래 수정·카테고리 편집): U2·U3 과 겹친다. 바텀시트를 하면 U2 는 필요 없고, U3 은 시트 안 삭제 흐름으로 정한다.
- 4단계 월 예산 + 결제수단·시각: BE + **DB(운영 마이그레이션 1회)**. 대시보드 이해도("이번 달 얼마나 써도 되나")에 가장 큰 효과지만 크기 L.

## 확인했지만 넣지 않은 것
- 금액 입력: `inputmode="numeric"`, +1천/+1만/+5만, 저장 버튼에 금액 표시, 저장 뒤 같은 카테고리 유지, 빠른 입력·메모 자동완성이 이미 있다(`index.html:51-59`, `record.js:303, 386-441`). 큰 마찰 없음.
- 저장 실패 시 입력 보존, 이중 제출 방지(`record.js:315-357`), 삭제 버튼 터치 높이 44px(`components.css:60`).
- 카테고리 관리 → 이력 → 뒤로 포커스 유실(`qa-report.md:1335` D1)은 지금 코드에서 로딩 뒤 복귀로 고쳐져 있다(`category-manager.js:363`).
- 첫 실행·가입 온보딩: 사용자가 이미 가입해 쓰고 있어 효과가 작다.

## 열린 질문
1. U3: 삭제 되돌리기 시 같은 날짜 안 순서가 바뀌는 것을 받아들일지(아니면 바텀시트 단계로 미룰지).
2. U5: 카테고리 블록 "기본 접힘" 과 "목록을 위로" 중 어느 쪽.
3. U2·U3 를 따로 할지, 3단계 바텀시트를 먼저 할지.
