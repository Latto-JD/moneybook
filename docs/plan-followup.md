## 1. 목표

운영 DB 를 건드리지 않는 작은 정리와 해·달 아이콘 모드 전환을 먼저 끝낸다(1단계). 그다음 큰 기능을 DB 변경이 없는 것부터 단계별로 진행하고, 운영 마이그레이션이 필요한 기능은 마지막 단계 하나로 모아 사용자가 마이그레이션을 한 번만 하도록 한다.

## 6. 1단계 상세

### 6.1 해·달 아이콘 모드 전환 (#3)

**선택지 비교** (자동/라이트/다크 3상태는 모든 안에서 유지)

| 안 | 모양 | 장점 | 단점 |
|---|---|---|---|
| A. 순환 버튼 1개 **[권장]** | 헤더에 지금 모드의 아이콘 + 글자(예: 해 "라이트", 달 "다크", 반쪽 원 "자동"). 누를 때마다 자동 → 라이트 → 다크 → 자동 | 지금 select 와 폭이 비슷해(약 80px) 360px 헤더 배치(C-T9)가 유지된다. 새 컴포넌트가 아니다 | 다음 상태가 무엇인지 미리 보이지 않는다(접근 이름으로 보완) |
| B. 세그먼트 3칸(아이콘 + 글자) | 자동/라이트/다크 버튼 3개, `aria-pressed` | 세 상태가 한눈에 보인다. 기존 세그먼트 패턴 재사용 | 글자까지 넣으면 약 190px 이 필요해서 360px 에서 이름 칸이 40px 아래로 줄어든다(C-T9 위반). 아이콘만 넣으면 "선택 글로" 요청과 어긋난다 |
| C. 메뉴 버튼 | 아이콘 버튼을 누르면 작은 목록(아이콘 + 글자 3항목, `menuitemradio`)이 열린다 | 명시적으로 고를 수 있고 공간도 적게 쓴다 | 새 컴포넌트(포커스 이동, Esc, 바깥 클릭, 화살표 키)라 3단계 바텀시트급 검증이 필요하다 |
| D. select 유지 + 앞에 아이콘 | 지금 select 앞에 지금 모드 아이콘만 붙인다 | 테스트 변경이 가장 적다 | 옵션 목록 안에는 아이콘을 넣을 수 없다(네이티브 select 한계). "아이콘으로" 요청을 절반만 만족 |

**권장 A 의 세부 사항**

- 마크업: `<button type="button" id="theme-toggle" class="btn btn--ghost btn--sm theme-toggle">` 안에 장식 아이콘 `<span class="icon icon--theme-…" aria-hidden="true">` + 보이는 글자 `<span>`(자동/라이트/다크). 지금의 `<select>` 와 visually-hidden 라벨은 제거한다.
- 접근 이름: 보이는 글자를 포함한다(WCAG 2.5.3). 예: `aria-label="화면 모드: 라이트. 누르면 다크로 바뀌어요"`. 상태가 바뀌면 접근 이름을 갱신하고, 화면에 보이지 않는 `role="status"` 영역에 "다크 모드" 처럼 짧게 알린다(포커스된 버튼의 이름 변화는 스크린리더마다 읽지 않을 수 있기 때문). 기존 `#flash` 토스트는 저장 메시지용이라 쓰지 않는다.
- `aria-pressed` 는 쓰지 않는다(켜짐/꺼짐 2상태 의미라 3상태와 맞지 않는다).
- 순서: 자동 → 라이트 → 다크 → 자동(OQ-4). `js/lib/theme.js` 에 순수 함수 `nextTheme(mode)` 를 추가하고 `initThemeSelect` 를 `initThemeToggle` 로 바꾼다. 저장·적용·storage 동기화 함수와 `theme-init.js` 는 그대로 둔다.
- 아이콘 3개(해, 달, 자동=반쪽 원)를 `public/icons/` 에 새로 만든다. 기존 아이콘과 같은 24px viewBox, stroke 1.8, CSS mask 방식이고 색은 글자색 토큰을 따른다. 외부 아이콘 세트·data: URI 는 쓰지 않는다(CSP). 새 파일에는 메타데이터를 넣지 않는다.
- 크기: 터치 높이 44px 이상, 포커스 링 `--shadow-focus`, 360px 에서 이름 칸 40px 초과(C-T9 기준 유지).
- 로그인 화면에는 지금처럼 전환 UI 를 두지 않는다(저장값만 따른다).

### 6.4 보이지 않는 문자 검증 통일 (#6)

- 규칙(이름·카테고리 공통, 서버가 기준이고 프론트도 같게):
  1. 지금의 C0 제어문자·DEL 거부는 유지한다.
  2. **추가로 거부:** 방향 제어 문자 U+202A–U+202E, U+2066–U+2069, U+200E, U+200F.
  3. **정규화 때 제거:** 폭 없는 문자 U+200B, U+2060, U+FEFF. 공백 정리 전에 지운다.
  4. 정규화한 뒤 비어 있으면 "1자 이상" 오류.
  - U+200C/U+200D(ZWNJ/ZWJ)는 이모지 조합(예: 가족 이모지)에 쓰이므로 허용한다.
- 정규식은 백엔드·프론트에 각각 **공통 모듈 하나**로 모은다(예: `src/backend/lib/text.js`, `public/js/lib/text.js`). 사용자 이름과 카테고리 이름은 이 모듈을 함께 쓴다. 길이 한도(20/15)와 오류 문구는 각자 유지한다.
- 기존 데이터: DB CHECK 는 바꾸지 않는다. 이미 저장된 이름은 그대로 보인다. 그런 이름을 PATCH 로 다시 저장하면 새 규칙이 적용된다(정규화 결과가 달라질 수 있음). 운영 DB 에 해당 데이터가 있는지 확인할 쿼리를 qa 리포트에 적는다(사용자가 선택적으로 실행).
- api.md: 2장(이름)·3A(카테고리 이름) 검증 문구를 갱신한다(backend). 응답 형식은 바뀌지 않는다.

### 6.5 "그 외 N개" 충돌 (#7)

- 표시 문구만 바꾸는 방법은 충돌을 막지 못한다. 묶음 라벨을 무엇으로 바꾸든 15자 이하이면 사용자가 같은 이름의 카테고리를 만들 수 있다.
- **[권장] 서버 금지 이름 + 묶음 행 접근 설명.**
  1. 카테고리를 추가하거나 이름을 바꿀 때 정규화된 이름이 `^그 외 \d+개$` 형태이면 400 `VALIDATION_ERROR` 로 막는다("'그 외 N개'는 차트 묶음 이름이라 쓸 수 없어요."). #6 과 같은 모듈에 두고, 프론트도 같은 검사를 한다. 이미 있는 이름은 그대로 두고 새로 쓰는 경우만 막는다(DB 변경 없음).
  2. 범례·표의 묶음 행에 화면에 보이지 않는 설명 "여러 카테고리를 합친 항목" 을 붙인다(`aria-describedby`). 묶인 이름 목록은 지금처럼 보인다.
  - 이렇게 하면 지금 라벨 문자열 `그 외 N개` 가 그대로라서 기존 테스트(`charts.test.js:147-195`, `categories-ui.spec.js:691, 741, 760`, `design.spec.js:1078`)를 바꾸지 않아도 된다.
- 대안: 서버 금지 없이 표시 구분만 한다(기울임·보조색). 충돌을 완전히 막지는 못한다. OQ-7.

- 사용자로서 이번 달 수입 가운데 얼마가 남았는지 비율로 보고 싶다.

### 13.5 #8 남은 돈 비율 (저축률)

- **정의:** `비율 = |남은 돈| ÷ 수입 × 100`, 소수 첫째 자리 반올림(`amountChange` 와 같은 반올림, `-0.0` 은 `0.0`). 남은 돈·수입은 `buildKpi` 값 그대로(보고 있는 달, 미래 날짜 거래 포함은 남은 돈과 같음).
- **문구 [권장]** (가치 판단 없이 사실만):

| 경우 | 문구 |
|---|---|
| 수입 > 0, 남은 돈 ≥ 0 | `수입의 32.5%가 남았어요` |
| 수입 > 0, 남은 돈 < 0 | `지출이 수입보다 20.0% 많아요` (= (지출 − 수입) ÷ 수입) |
| 수입 = 0, 지출 > 0 | `수입 기록이 없어 비율을 계산하지 않아요` |
| 수입 = 0, 지출 = 0 | 줄을 그리지 않는다 |

- **위치:** `.kpi--balance` 안 `.kpi-value` 바로 아래 새 줄 `<p class="balance-rate">`(보조 글자색, 빨강·초록 없음). `.kpi-extra` 클래스는 쓰지 않는다(기존 테스트가 수입·지출 두 칸의 `.kpi-extra` 를 센다). 읽는 순서: 남은 돈 → 비율 → 수입 → 지출. `#kpi` 의 `aria-live` 는 그대로.
- **구현:** 순수 함수 `balanceRate(income, balance)` → `null | { direction: 'left' | 'over' | 'none', percent, text }` 를 `lib/dashboard-data.js` 에 두고 단위 테스트(경계: 수입 0·지출 0, 남은 돈 0, 음수, 매우 큰 비율 예 수입 1원·지출 1억, 소수 반올림 .05 경계)를 붙인다. 화면 이름표에 "저축률" 이라는 단어는 쓰지 않는다(OQ-15).
- API 변경 없음.

### 13.6 #9 저장 되돌리기 토스트

**동작**
1. 새 기록 저장(201) 뒤: 토스트 `저장했어요` + [되돌리기]. 수정 저장(200) 뒤: `수정했어요` + [되돌리기]. 삭제는 지금처럼 `삭제했어요` 만(버튼 없음).
2. 되돌리기를 누르면:
   - 생성 → `DELETE /api/transactions/:id`. 204 와 404(이미 지워짐)는 성공으로 본다.
   - 수정 → `PUT /api/transactions/:id` 에 **수정 전 거래 전체 값**(type, amount, category, memo, date). `startEdit` 때 거래 객체 스냅샷을 따로 남긴다(지금 `state.orig` 는 type·category 만 있음).
   - 성공: 토스트를 글자만 `되돌렸어요`(4초)로 바꾸고 `refreshAll` + `notifyChanged`. 수정 되돌리기는 `state.month` 를 수정 전 날짜의 달로 옮긴다(저장 때 저장한 달로 옮기는 것과 대칭). 생성 되돌리기는 달을 바꾸지 않는다.
   - 실패: 404(수정 되돌리기)는 `이미 삭제된 기록이라 되돌리지 못했어요`, 그 밖의 400·500·네트워크 오류는 `되돌리지 못했어요. 목록에서 직접 고쳐 주세요.` 를 토스트 글자로 보여 준다. 401 은 기존 api.js 처리(로그인 화면).
3. **수정 되돌리기를 보이지 않는 경우:** 수정 전 카테고리가 사용 안 함(저장 때 `state.legacy` 가 있었음)이고 이번 수정이 (type, category) 를 바꾼 경우. 서버가 400 을 주기 때문이다(13.3). 이때는 글자만 `수정했어요`.

**마크업 · 접근성**
- `#flash` 는 **글자 전용**으로 그대로 둔다(role=status, 테스트 훅 27곳 유지). 그 바깥에 컨테이너 `<div class="toast" id="toast">` 를 두고 안에 `#flash` 와 `<button type="button" id="flash-undo" hidden>되돌리기</button>` 를 나란히 넣는다. `.toast` 클래스는 컨테이너로 옮기고, 글자와 버튼이 모두 비면 컨테이너를 숨긴다(`style.css` 의 `#flash:empty` 규칙을 대체). `components.css` 는 고치지 않는다.
- 버튼은 live 영역 밖에 있어서 상태 알림은 지금처럼 `저장했어요` 만 읽힌다. 버튼 접근 이름은 보이는 글자를 포함한다: `방금 저장한 기록 되돌리기` / `방금 수정한 내용 되돌리기`(WCAG 2.5.3). 높이 44px 이상, 포커스 링 보임, 라이트·다크 대비 4.5:1.
- 저장 뒤 포커스는 지금처럼 금액칸(연속 입력을 방해하지 않음). 토스트로 포커스를 옮기지 않는다. 버튼은 Tab 순서로 도달할 수 있다(DOM 위치는 지금 `#flash` 자리). 같은 일을 목록 행의 수정·삭제로도 할 수 있으므로 시간 제한이 일을 막지 않는다.
- 되돌리기 버튼에 포커스가 있는 상태에서 버튼이 사라지면 금액칸으로 포커스를 옮긴다(body 로 가지 않게).

**시간 · 경합**
- 버튼이 있는 토스트는 5초, 글자만 토스트는 지금처럼 4초. 포인터가 토스트 위에 있거나 포커스가 토스트 안에 있으면 타이머를 멈추고, 벗어나면 다시 5초를 센다(WCAG 2.2.1).
- 되돌릴 수 있는 것은 **직전 1건**뿐이다. 새 저장·삭제·`startEdit`(목록에서 수정 시작)·탭 밖 오류 토스트(`app.js:28`)가 생기면 이전 되돌리기는 사라진다. 그래서 "폼이 그 거래를 수정 중인데 되돌리기" 경우는 생기지 않는다.
- 되돌리기 요청 중에는 버튼을 disabled 로 두고, 저장 제출·삭제도 막는다(D2 `submitting` 과 같은 방식, 두 번 눌러도 요청 1번). 저장 요청 중에는 되돌리기 버튼이 없다.
- 탭 전환·월 이동 중에도 토스트는 시간 안에서 유지되고, 되돌리기 결과는 그 시점의 화면을 다시 불러온다.
- 판단을 순수 함수로 뺀다(예: `lib/undo.js` 의 `undoPlan(kind, before, after, legacyBefore)` → `null | { method, id, body, month }`) 그리고 단위 테스트를 붙인다.

API 변경 없음(기존 4.3 PUT, 4.4 DELETE). backend 는 api.md 4장에 "되돌리기는 기존 PUT/DELETE 를 쓴다, 사용 안 함 카테고리로 되돌리는 PUT 은 400" 한 줄만 적는다(B-S1).

### 13.7 #10 수입 인사이트 (I1 · I2)

**I1 수입 감소** (응답 키 `incomeDrops`, R4 exceeded 의 수입판)
- 조회 `month` 가 `today` 의 달보다 **앞선 달(끝난 달)** 일 때만 판정한다. 이번 달·미래 달은 빈 배열.
- 카테고리별(수입). baseline = 직전 3개 달력월 중 그 카테고리 수입이 있는 달의 월 합계 평균. 기록 있는 달 2개월 미만이거나 baseline 10,000원 미만이면 판정하지 않는다(R4 와 같은 상수).
- 조건: `currentTotal ≤ baseline × 0.8` (정수 연산: `currentTotal × k × 5 ≤ S × 4`, k = 기록 있는 달 수, S = 그 합계). `currentTotal = 0`(그 달에 그 카테고리 수입 없음)도 포함. 반복 거래도 합계에 포함(R4 exceeded 와 같음).
- 항목: `{ category, currentTotal, baseline(원 반올림), ratio(currentTotal/baseline, 소수 둘째) }`. 정렬: ratio 오름차순 → 사용자 `sortOrder`(income) → 가나다. 카테고리당 1개, 개수 제한 없음.
- 문구(프론트): `급여: 9월 수입 1,800,000원으로 평소 월 평균 2,500,000원보다 28% 적어요`, 0원이면 `급여: 9월에는 수입 기록이 없어요 (평소 월 평균 2,500,000원)`. 라벨 `평소보다 적음`, 장식 아이콘 `↘`.

**I2 반복 수입 누락** (응답 키 `missingIncome`)
- 조회 `month` 가 `today` 의 달과 같을 때만 판정한다. 다른 달은 빈 배열.
- 그룹: R3 와 같은 그룹 키·월간 조건(같은 날 1건, 3회 이상, 간격 26~35일, 금액 중앙값 ±10%), **수입·월간만**. 단 R3 의 비활성 제외 대신 `마지막 날짜 + 70일 ≥ today`(한 번 빠진 것까지)를 쓴다. R3 `recurring` 응답 결과는 바뀌면 안 된다(감지 함수에 옵션을 추가하는 식, 기존 R3 단위 테스트 그대로 통과).
- `expectedDate = 마지막 날짜 + floor(간격 중앙값)` (R3 `nextDate` 와 같은 계산).
- 조건: `today ≥ expectedDate + 3일`(유예), 그리고 이번 달 거래 중 같은 그룹 키 거래가 **하나도 없다**(미래 날짜로 미리 입력한 거래 포함, 이 판정만은 `date > today` 도 본다). 마지막 거래가 이번 달에 있으면 대상이 아니다.
- 항목: `{ memo, category, amount(중앙값 반올림), lastDate, expectedDate }`. 정렬: expectedDate 오름차순 → memo 가나다. 사용 안 함 카테고리도 계속 판정(R3 와 같음).
- 문구(프론트): `급여 2,500,000원: 매달 들어오던 수입이 이번 달엔 아직 없어요 (마지막 9월 25일)`. 메모가 없으면 카테고리 이름(R3 문구와 같은 방식). 라벨 `아직 없음`, 장식 아이콘 `…`.
- 알려진 겹침: R3 비활성 제외 전(마지막+35일 이내)에는 R3 "반복" 줄(다음 예정이 지난 날짜)과 I2 줄이 함께 보일 수 있다. 이번에는 그대로 둔다.

**응답 · 화면**
- `GET /api/insights` 응답에 키 2개를 **추가만** 한다. 기존 키·필드·정렬은 그대로라 구버전 프론트와 호환된다. 카테고리 이름 변경·사용 안 함의 영향은 R4·R3 와 같다(api.md 6.4 표에 두 열 추가).

### 13.8 #14 화면 모드 라이트↔다크 2상태

**처음 볼 모드 [권장]:** 저장값이 없거나 'auto'·잘못된 값이면 **OS 설정을 따른다**(지금과 같은 화면). 버튼은 지금 실제로 보이는 모드(OS 가 다크면 "다크")를 보여 주고, 누르면 **반대 모드를 저장**한다. 저장한 뒤에는 OS 설정이 바뀌어도 저장값을 따른다. "OS 따르기"로 돌아가는 UI 는 두지 않는다(저장소를 지우면 돌아감). 대안: 저장값이 없으면 항상 라이트로 시작(OQ-14).

**theme.js**
- `MODES = ['light','dark']`, `MODE_LABEL` 에서 auto 제거. `parseTheme`/`readTheme` 는 그대로 두고 'auto' 는 "저장값 없음" 이라는 내부 뜻으로만 쓴다.
- 새 순수 함수: `systemTheme(win)`(`matchMedia('(prefers-color-scheme: dark)')`, 없거나 예외면 'light'), `effectiveTheme(stored, system)`(stored 가 light/dark 면 그것, 아니면 system).
- `nextTheme(mode)`: dark → light, 그 밖 → dark. `toggleLabel(mode)`: `화면 모드: 라이트. 누르면 다크로 바뀌어요` / `화면 모드: 다크. 누르면 라이트로 바뀌어요` ("(으)로" 제거, 둘 다 "로").
- `initThemeToggle`: 시작할 때 실제 모드를 표시. 클릭 → `next = nextTheme(실제 모드)` 를 `saveTheme`·`applyTheme`, 표시 갱신, `#theme-status` 에 `다크 모드`/`라이트 모드`. storage 이벤트: 다시 읽고, 키가 지워졌으면 `data-theme` 을 지우고 OS 모드를 표시. 저장값이 없을 때만 `matchMedia` change 이벤트로 버튼 표시를 갱신(색은 CSS 가 이미 바꿈).
- 'auto' 저장값: 지금까지 코드는 'auto' 를 저장한 적이 없다(키 삭제). 혹시 있어도 "저장값 없음" 으로 보고 지우지 않는다(별도 정리 코드 없음).

**theme-init.js:** 바꾸지 않는다. 지금도 light/dark 만 적용하고 나머지는 CSS(OS) 에 맡긴다. 깜빡임 방지 동작(C-T4)은 그대로.

**index.html · CSS · 아이콘**
- 정적 마크업을 `data-mode="light"`, `icon--theme-light`, 글자 "라이트" 로 바꾼다. 모듈이 실행되면 바로 실제 모드로 바뀐다(OS 다크·저장값 없음 사용자는 아주 잠깐 글자 "라이트" 가 보일 수 있다. 색은 바뀌지 않으므로 허용, 13.11).
- `public/icons/theme-auto.svg` 를 지우고 `style.css:40` `.icon--theme-auto` 규칙을 지운다. 배포 아이콘은 17개(원본 15 + theme 2).
- 접근 방식은 1단계와 같다: `button` + 접근 이름 "화면 모드: …"(보이는 글자 포함), `aria-pressed`·`role="switch"` 는 쓰지 않는다(보이는 글자가 상태마다 바뀌는 버튼이라 눌림 상태 패턴과 맞지 않는다).
- 로그인 화면은 그대로(전환 UI 없음, 저장값 또는 OS).
